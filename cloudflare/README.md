# ميدواي على Cloudflare Workers + D1

النسخة الجديدة تجمع واجهة React/Vite وHono API في **Worker مع Static Assets**، وقاعدة مشتركة **D1**. لا تحتاج عملية Bun دائمة أو ملف SQLite على خادم. اخترنا Worker واحدًا بدل Pages مع Worker منفصل لتبسيط النشر، مع نفس الواجهة والصلاحيات.

## الحالة الفعلية

تم اختبار التطبيق داخل `workerd` وD1 المحليين: إنشاء المدير والحسابات، العملاء والطلبات والمرفقات، واجهة الكمبيوتر والموبايل، العزل بين الموظفين، الحفظ المتزامن، إلغاء المعاملات عند الفشل، وبقاء البيانات والجلسات عند إعادة تشغيل Worker. تم أيضًا اختبار تجميع حزمة Worker دون نشر.

أنشأ المستخدم قاعدة D1 باسم `midway-workspace`، وأضيف معرفها الظاهر في لوحة حسابه إلى `wrangler.jsonc`. لم يتم بعد تطبيق الترحيل على القاعدة السحابية أو نشر Worker. لا توجد بيانات دخول Cloudflare متصلة بهذه البيئة؛ فحص التجميع المحلي لا يثبت إمكانية الوصول إلى القاعدة. سكربت النشر يرفض أي معرف مؤقت قبل تنفيذ أوامر النشر.

## خطوات النشر

1. أنشئ حساب Cloudflare على الخطة المجانية. راجع شروط الحساب وحدوده الحالية؛ لا نضمن سياسات التسجيل المستقبلية أو مجانية استخدام يتجاوز الحدود، ولا تُفعّل اشتراكًا مدفوعًا لهذه التجربة.
2. من **Storage & Databases → D1** (قد يظهر تحت **Compute & AI**) أنشئ قاعدة باسم `midway-workspace`. لا تختَر خطة مدفوعة.
3. انسخ **Database ID** إلى خانة `database_id` في `wrangler.jsonc`. هذا معرف إعداد، وليس كلمة مرور. يمكن مشاركته لإكمال الإعداد، بعكس API Tokens والقيم السرية.
4. اربط مستودع GitHub `eslammhamdc-ship-it/eslaaaaaaaaaam-3237` والفرع `codex/midway-branch-workspace` باستخدام **Workers & Pages → Create application → Import a repository**، واختر مشروع Worker.
5. Build command: `bash deploy/build-cloudflare.sh`. Deploy command: `bash deploy/deploy-cloudflare.sh`. Root directory: جذر المستودع (فارغ). يجب أن يملك رمز Workers Builds صلاحية نشر Worker وتطبيق ترحيلات D1 على القاعدة المحددة؛ لا تستخدم رمزًا عامًا بصلاحيات أكثر من اللازم.
6. سكربت النشر يطبّق ترحيل D1 ثم ينشر Worker والواجهة. إذا رفضت صلاحيات D1، أكمل الترحيل من جهازك بعد `wrangler login` باستخدام `bunx wrangler d1 migrations apply midway-workspace --remote`، أو امنح رمز البناء صلاحية D1 المحددة ثم أعد النشر. لا ترسل الرمز في المحادثة.
7. في إعدادات Worker أضف **Secret** باسم `MIDWAY_SETUP_TOKEN` بقيمة عشوائية طويلة تحتفظ بها بنفسك. اترك `MIDWAY_ALLOW_SETUP=true` لإعداد أول حساب. الواجهة ترفض إنشاء أول مدير بدون الرمز حتى لو نُشر الموقع قبل إضافته.
8. افتح رابط `workers.dev` الفعلي الذي تعطيه Cloudflare وأدخل رمز الإعداد، ثم أنشئ حساب مدير الفرع. أضف مديري الطيران والمبيعات والموظفين من إدارة الفريق.
9. بعد إنشاء المدير، غيّر `MIDWAY_ALLOW_SETUP` في `wrangler.jsonc` إلى `false` وأعد النشر حتى يظل الإعداد مغلقًا في الإصدارات التالية. احتفظ بالسر في إعدادات Worker ولا تحفظ قيمته في GitHub أو المحادثة.

يمكن تنفيذ النشر أيضًا من جهاز موثوق عبر `bunx wrangler login` ثم `bash deploy/build-cloudflare.sh` و`bash deploy/deploy-cloudflare.sh`. إضافة Secret ممكنة عبر `bunx wrangler secret put MIDWAY_SETUP_TOKEN`، حيث تدخل القيمة في المطالبة الآمنة، وليس ضمن الأمر أو سجل المحادثة.

## حفظ البيانات وحدود الخطة

- البيانات والحسابات والمرفقات في D1، وتبقى منفصلة عن عمر Worker ونشره. حذف قاعدة D1 أو تغيير معرف الربط قد يحذف البيانات أو يوجّه إلى قاعدة مختلفة؛ هذه ليست حماية من أخطاء الإدارة.
- كل طلب محفوظ كسجل مستقل في `flight_requests`؛ لا يُجمع الفرع كله في سجل SQLite واحد. مراجعة الطلبات المتزامنة تستخدم D1 batch ذريًا وحارس مراجعة يمنع ضياع التحديثات.
- حد المرفق في هذه النسخة **1 MiB للملف و4 MiB لإجمالي الملفات الجديدة في الحفظ الواحد**، لأن D1 يحد حجم السجل إلى 2 MB. الحد ظاهر في النموذج ويُفرض على الخادم. لا نعتمد على R2 أو خدمة تخزين مدفوعة. للملفات الأكبر نحتاج تصميم تخزين منفصل وتحققًا جديدًا من خطته.
- إجمالي سعة D1 والقراءات والكتابات وطلبات Workers وCPU له حدود مجانية. التخزين ليس غير محدود، والخطة المجانية ليست SLA للعمل الإنتاجي. نجاح المحاكي لا يثبت الالتزام بميزانية CPU في كل سيناريو؛ اختبر التسجيل والدخول وأكبر مرفق مسموح على الخدمة الفعلية وراجع Metrics قبل العرض.
- هذا التطبيق لفرع واحد. للشركات المستقلة أنشئ Worker وقاعدة D1 وسر إعداد مستقلين؛ لا تربط شركات مختلفة بنفس قاعدة البيانات.

## كلمات المرور

التشغيل المحلي يستخدم scrypt، ويظل قادرًا على التحقق من حسابات Bun القديمة ذات Argon2. في Worker، اشتقاق PBKDF2-HMAC-SHA256 القياسي (600,000 دورة وsalt عشوائي مستقل) يتم في المتصفح عبر WebCrypto على HTTPS، لتجنب تكلفة تشفير كلمة المرور داخل حد CPU المجاني. الخادم يخزن SHA-256 للناتج، وليس كلمة المرور أو الناتج القابل للاستخدام للدخول. الجلسات تظل رموزًا عشوائية HttpOnly/SameSite.

بيانات تحدي الدخول (salt وعدد الدورات) ليست سرية. ناتج الاشتقاق المُرسل للخادم **مكافئ لكلمة المرور** ويجب ألا يُسجل أو يُخزن في المتصفح أو يُشارك. واجهة API المباشرة في Worker تحتاج بروتوكول التحدي والناتج، ولا تقبل كلمة المرور النصية كما في نسخة Bun. اختبارات API والمتصفح تتحقق من ذلك ومن تغيير كلمة المرور وإلغاء الجلسات.

لا تستورد حسابات Argon2 القديمة مباشرة إلى D1 وتتوقع عملها. لا يتم ترحيل البيانات المحلية أو المرفقات أو كلمات المرور إلى Cloudflare تلقائيًا. ابدأ بيانات التجربة بحسابات جديدة؛ النقل الفعلي يحتاج خطة ترحيل خاصة وإعادة تعيين كلمات المرور القديمة. ملفات `.midway` المحلية محفوظة ولم تُرفع.

## اختبارات وإعداد محلي

```sh
bun install --frozen-lockfile
bun run typecheck
bun run lint
bun run test:workspace
cd packages/web && bun run build && cd ../..
bunx tsc -p cloudflare/tsconfig.json
WRANGLER_SEND_METRICS=false bunx wrangler deploy --dry-run --outdir .cache/cloudflare-build
python tests/cloudflare_smoke.py
```

اختبار Cloudflare ينشئ قاعدة D1 ومحاكيًا وأسرارًا مؤقتة محليًا، ويشغّل المتصفح على منفذ 4206. لا ينشئ أي موارد سحابية ولا يقرأ بيانات عملك. يحتاج Python Playwright وChromium. الصور في `.cache/cloudflare-browser`.

للتطوير اليدوي: `bunx wrangler d1 migrations apply midway-workspace --local` ثم أنشئ `.dev.vars` محليًا بقيمة `MIDWAY_SETUP_TOKEN` الخاصة بك (الملف مستبعد من Git) وشغّل `bunx wrangler dev --local`. استخدم `MIDWAY_SECURE_COOKIES=false` في إعداد محلي منفصل فقط عند الاختبار عبر HTTP؛ لا تغيّر إعداد HTTPS المنشور.

## النسخ الاحتياطية

قبل أي ترحيل لاحق خذ نسخة D1 من حسابك الموثوق، مثل `bunx wrangler d1 export midway-workspace --remote --output backups/midway.sql`، واختبر الاستعادة على قاعدة منفصلة. مجلد `backups/` مستبعد من Git. النسخة تحتوي حسابات وبيانات خاصة فلا تشاركها علنًا. لا تعتبر إعادة نشر Worker نسخة احتياطية للقاعدة.

المراجع الرسمية: [Workers Free limits](https://developers.cloudflare.com/workers/platform/limits/)، [D1 limits](https://developers.cloudflare.com/d1/platform/limits/)، [D1 transactions through batch](https://developers.cloudflare.com/d1/worker-api/d1-database/#batch).
